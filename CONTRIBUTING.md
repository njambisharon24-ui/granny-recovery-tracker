Thank you for your interest in contributing to Granny Recovery Tracker!

How to contribute

1. Search open issues and pick one labeled `good first issue` or `help wanted`.
2. If you want to work on something not listed, open an issue describing your idea first.
3. Fork the repository and create a feature branch named `feat/some-short-description` or a fix branch `fix/short-desc`.
4. Write clear commit messages and reference the issue number in your PR body.
5. Make sure tests pass and add tests for new features when possible.

Hacktoberfest & PR guidelines
- Label your PR with `hacktoberfest` if it fixes or implements an eligible issue.
- Ensure your PR follows the code style and includes documentation for changes.
- For AI models or summarization features, list the model name and inference instructions and use an open-weight model (e.g., Gemma) per project policy.

Issue templates and expectations
- Provide reproducible steps and sample data for bugs.
- For feature requests, include user stories and acceptance criteria.

Code reviews
- Keep PRs small and focused to get faster reviews.
- Address review comments promptly and keep the PR tidy.

Security & privacy
- Do not commit secrets; use environment variables for credentials.
- For any health-related data examples, use anonymized or synthetic data only.

Thank you! We welcome contributors of all levels.
